# Repository instructions

This file is the short operational guide for AI coding agents and contributors.
Read `README.md` and `docs/architecture.md` before making broad changes.

## Product invariants

- The product is Android-only. Do not restore or generate an `ios/` target.
- It is entirely free: no ads, billing, subscriptions, premium flags, or gated
  features.
- Documents are processed on-device. Do not add uploads, accounts, analytics,
  tracking, or an application backend.
- Preserve Android default-PDF-viewer behavior and both cold- and warm-intent
  handling.
- Preserve scoped-storage behavior. Shared files must go through MediaStore or
  Android's Storage Access Framework.
- Never log document contents, passwords, keystore secrets, or private paths in
  production diagnostics.

## Where changes belong

- Screens and feature-specific orchestration: `lib/features/<feature>/`
- Shared domain models: `lib/domain/entities/`
- PDF operations: `lib/services/pdf/`
- Save/export behavior: `lib/services/storage/`
- Preferences: `lib/data/local/app_preferences.dart`
- Recent-file persistence: `lib/data/local/database/` and
  `lib/data/repositories/recent_files_repository.dart`
- Provider wiring: `lib/core/di/providers.dart`
- Routes: `lib/core/routing/app_router.dart`
- Android intents and storage calls:
  `android/app/src/main/kotlin/com/pdftoolkit/pdf_tool/MainActivity.kt`
- Dart side of Android intent handling:
  `lib/services/platform/android_integration_service.dart`

Keep widgets thin. Put validation, temporary-output creation, and exception
translation in `PdfProcessingService`; put low-level document manipulation in
`PdfService` and its helpers.

## Important contracts

- Page numbers exposed to UI and domain code are one-based unless a local API
  explicitly documents otherwise.
- `PdfPageOperation` is the source of truth for the unified page organizer.
- A processing operation writes to a temporary path first. The save flow then
  moves or copies the result into app-managed storage and optionally exports it.
- Recent-file records should reference the durable app-managed copy, not a
  temporary input or cache file.
- PDF view intents may contain `content://` URIs. Kotlin copies them to private
  cache before passing a filesystem path to Flutter.
- Method-channel names and method strings are an API. Update Kotlin, Dart, and
  tests together when changing them.
- `app_database.g.dart` is generated by Drift but committed to source control.

## Editing rules

- Follow existing Dart formatting and use `dart format`.
- Reuse existing providers and shared widgets before introducing new global
  state or duplicate UI components.
- Convert technical exceptions with `userFriendlyError` or typed app
  exceptions before showing them to users.
- Keep expensive PDF/image work asynchronous and report progress through the
  existing job runner where appropriate.
- Clean up temporary files on both success and failure paths.
- Avoid broad dependency upgrades unless required for the task; PDFium and
  Android build changes need a full APK build.
- Never edit generated files manually. Regenerate Drift output with
  `dart run build_runner build --delete-conflicting-outputs`.

## Verification

Run the smallest relevant test while iterating, then before handoff run:

```bash
dart format --output=none --set-exit-if-changed lib test integration_test
flutter analyze
flutter test
```

For changes involving PDFium, plugins, Android code, manifests, Gradle, icons,
or storage channels, also build an APK:

```bash
flutter build apk --debug
```

Release signing secrets belong only in ignored `android/key.properties` and an
ignored keystore file. Never print, commit, or copy those values into docs.

## Documentation updates

Update `README.md` for user-visible capabilities or build changes. Update
`docs/architecture.md` when adding a layer, route, provider family, native
channel method, persistence mechanism, or materially different file flow.
